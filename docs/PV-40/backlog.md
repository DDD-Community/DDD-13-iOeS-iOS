## 1. 검수 결과 알림 API 연동 (서버 개발 예정, 호출 시점 논의 중)

서버가 오픈·반려 결과를 내려주는 API 를 신설하기로 했다. 호출 시점이 아직 정해지지
않아 연동은 뒤로 미룬다.

**지금 동작하는 방식(임시)**
`GET /v1/users/me/my-spots` 로 내 스팟 상태를 읽어, 로컬에 기록해 둔 이전 상태와
비교해 결과 도착을 감지한다. 구현은 `SpotReviewNoticeController` 한 곳에 모여 있어
전용 API 가 나오면 `refresh()` 만 교체하면 된다. 스낵바·인디케이터·소멸 정책은 그대로
재사용된다.

**임시 방식의 한계**
- 앱을 지웠다 깔거나 기기를 바꾸면 기록이 없어 결과 안내를 놓친다
- `my-spots` 는 6 개 단위 페이징인데 첫 페이지만 읽는다. 등록한 스팟이 7 개 이상이면
  뒤쪽 스팟의 결과를 잡지 못한다

**서버에 요청한 사항**
- **응답에 `spotId` 포함**: 스낵바 액션이 "오픈된/반려된 스팟 상세로 이동" 이라
  YN 만으로는 어디로 갈지 알 수 없다
- **확인 처리(ack) 방법**: 읽기 전용 YN 이면 닫아도 다음 호출에서 다시 Y 가 와서
  스낵바가 계속 뜬다. 확인 처리 엔드포인트가 있거나, "해당 스팟 상세를 조회하면
  자동 확인" 같은 규칙이 필요하다
- **건별 목록 형태**: 오픈·반려가 동시에 있을 때 하나씩(반려 우선) 보여주려면
  `[{ spotId, result, decidedAt }]` 처럼 건별로 와야 한다

**호출 시점에 대한 iOS 의견**
- 제외: `refresh token 갱신 시점` — 401 발생 시 인터셉터가 자동 수행하므로 시점을
  예측할 수 없고, 네트워크 계층이 화면 상태를 바꾸게 된다. 동시 401 시 중복 호출도 생긴다
- 추가: `앱 포그라운드 복귀` — 앱을 종료하지 않고 백그라운드에 두는 경우가 많아
  콜드 스타트만으로는 며칠 동안 결과를 받지 못할 수 있다
- 추가: `오픈 신청 / 신청 철회 직후` — 저장 탭 인디케이터가 즉시 켜지고 꺼져야 한다
- 화면 단위보다 **앱 진입 단위**가 기획 1-a("첫 진입 화면이 마이페이지인 경우에도
  동일하게 노출")를 정확히 만족한다

## 2. 서버 작업이 필요한 것

| 항목 | 내용 |
|---|---|
| 반려 배너 [스팟 오픈 철회] Dev 확인 | 기존 `DELETE .../publications` 연결은 완료했다. OpenAPI 에 `REJECTED` 처리 결과가 명시되지 않아 실제 Dev 응답 확인이 필요하다 |
| 공개 ON/OFF 토글 — 재검수 없는 전환 미지원 | 기획 원칙: "승인 이력이 있는 스팟은 이후 ON/OFF 를 검수 없이 자유롭게 전환 가능. OFF 는 DRAFT 와 다른 별도 상태로 취급, OFF→ON 전환 시 재검수 없음." 그런데 서버 상태 모델은 `DRAFT/PENDING/RE_REVIEW_PENDING/PUBLISHED/REJECTED` 5 개뿐이라 "승인 이력 있는 OFF" 를 나타낼 상태가 없다. `DELETE .../publications` 는 해제 후 상태가 **항상 DRAFT** 이고, `POST .../open-requests` 는 DRAFT 에서 호출하면 **항상 PENDING(재검수)** 으로 간다. 지금 구현(토글 OFF→DRAFT, 토글 ON→매번 재검수 시트)은 이 원칙과 다르다. 앱만으로는 못 고치고 서버에 상태 또는 재검수 없는 전환용 엔드포인트 추가가 필요하다 |
| 큐레이션 출처명 | 기획 3.7 은 "한국관광공사"/"Pickflow 운영자" 같은 소스별 고정값을 요구하는데 API 에는 `isCurated: Bool` 뿐이다 |
| 비공개 스팟 북마크 해제 | 비공개 스팟은 조회가 404 인데 북마크 해제도 막히는지 미확인. 막히면 보관함의 "저장 목록에서 삭제" 가 실패 토스트로 빠진다 |
| 저장된 스팟 목록의 `likeCount` | 보관함 카드 시안은 "윤슬 · 추천 34" 인데 `SavedSpotItem` 에는 `bookmarkCount` 만 있고 `likeCount` 가 없다. 지표를 아예 노출하지 않고 있다(잘못 넣었다가 이번에 되돌렸다) |

## 3. 기획·디자인 확정이 필요한 것

| 항목 | 내용 |
|---|---|
| 검수중 상태의 "스팟 삭제하기" | 시안엔 노출되는데 API 는 `SP011` 로 막는다. 숨길지, 노출하고 안내를 띄울지 |
| 반려 상태의 추천 버튼 | 기획 3.8 은 "버튼 자체 없음", 시안엔 있다. 시안에는 추천 카운트가 없어 시안 실수일 가능성 |
| 보관함 "삭제됨" 카피 | 시안이 없어 서버 문서의 '삭제된 스팟' 표현을 따라 "등록한 유저가 / 삭제한 스팟이에요" 로 두었다 |
| 북마크 사전 안내 형태 | 카피는 기획에 있으나 노출 형태(토스트/인라인/시트)가 없어 토스트로 두었다 |
| 오픈 취소 확인 단계 | 기획 3.6 의 확인 모달은 없어지고 토글 하나로 정리된 것으로 보인다(승인 이력 있으면 재검수 없이 자유 전환 원칙과 일치). 다만 서버가 이 원칙을 아직 지원하지 않아(위 "공개 ON/OFF 토글" 항목 참고) 지금은 OFF 가 곧 DRAFT 라 되돌리려면 재검수를 거쳐야 한다 — 서버 작업이 끝나야 확인 단계 필요 여부도 최종 판단 가능 |
| 미리보기 시트의 [저장하기] | 지도 미리보기 시안에 북마크 버튼이 없다. 의도적으로 뺀 것인지, 프레임에서 생략된 것인지 |
| 큐레이션 스팟 **상세** | 타 유저 스팟 상세는 받아서 구현했다. 큐레이션 스팟 상세는 아직이라 지금은 뱃지 없이 추천만 노출된다. 기획 3.7 의 출처 표기("한국관광공사" 등)는 API 필드도 없다 |

## 4. 앱 내부에 남은 것 (외부 의존 없음)

| 항목 | 내용 |
|---|---|
| `ArchiveScreenContent` 사본 | `ArchiveView` 본문을 옮겨 둔 사본이고 스냅샷 테스트에서만 쓰인다. 실제 뷰를 고칠 때 사본도 같이 고치지 않으면 검증 대상과 어긋난다(이번에 실제로 한 번 어긋났다) |
| `test.yml` 스냅샷 스킵 목록 | 클래스를 이름으로 하나씩 나열해 새 클래스를 만들 때마다 손이 간다. `*SnapshotTests` 패턴으로 한 번에 거르는 편이 낫다 |
| CI 에 릴리즈 빌드 없음 | `valid_build` 가 `-configuration Debug` 로만 빌드한다. `#if DEBUG` 누락으로 릴리즈 빌드가 깨진 적이 있는데 CI 가 잡지 못했다 |
| 신규 등록 폼의 이탈 확인 | 재신청 모드에만 걸어 두었다. 신규 등록도 채운 내용을 잃는 건 같아 넓히는 게 맞을 수 있다 |
| 중앙 팝업 컴포넌트 중복 | 오픈 완료·저장 삭제·이탈 확인 세 팝업의 뼈대가 같다. 공용 컴포넌트로 뽑을 만하다 |
| 다른 화면의 `.sheet` | iOS 26 은 시트를 띄운 카드로 그린다. 확인 시트는 오버레이로 바꿨지만 `ReportSheet`, 날짜·시간 피커, 지도 미리보기 시트는 그대로다 |
