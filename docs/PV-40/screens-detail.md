# 확인 필요 — 기획서/API와 어긋나는 지점

## 서버 스펙과 충돌 (블로커)

**1. 검수중 상태에 "스팟 삭제하기"가 노출됨**
시안의 `Detail-Reviewing-My-Sub` 하단에 "스팟 삭제하기"가 그대로 있는데, API는 PENDING/RE_REVIEW_PENDING 삭제를 `409 SP011`로 막는다("오픈 신청을 먼저 철회한 뒤 삭제").
→ 검수중엔 항목을 숨길지, 노출하되 탭 시 "오픈 신청을 먼저 철회해주세요" 안내를 띄울지 결정 필요.

**2. 반려 배너의 [스팟 오픈 철회]가 호출할 API가 없음**
반려(REJECTED) 배너의 [스팟 오픈 철회]도 기존 `DELETE .../publications`에 연결한다. OpenAPI에는 REJECTED 처리 결과가 명시되지 않아 Dev 응답 확인이 필요하다.
→ 이 버튼이 실제로 뭘 해야 하는지 정의 필요. 추정 후보: (a) 반려 배너만 닫고 일반 나만보기 화면으로 복귀(=클라 로컬 처리), (b) 서버에 REJECTED→DRAFT 전이 API 신설. 서버 확인 필요.

**3. 반려 상태에 추천(👍) 버튼이 노출됨**
기획 3.8은 "나만보기·검수중·반려 상태에서는 버튼 자체 없음"이고, API도 비공개 유저 스팟은 `isLikeable=false` + 좋아요 호출 시 `SL003`.
→ 시안이 맞다면 비활성 상태로 노출인지, 기획대로 제거인지.

**4. 재신청이 "등록"인지 "수정"인지**
시안은 "기존 등록 플로우와 동일", 토스트도 "나만의 스팟이 등록되었어요!"인데, API 구조상 재신청은 새 스팟 생성이 아니라 **기존 스팟 `PUT` 수정 → `POST open-requests`** 2단계다(스팟 ID 유지, 좋아요/북마크 승계).
→ 등록 API로 새로 만들면 기존 스팟이 중복으로 남는다. 재신청은 수정 API로 가는 게 맞는지 확인 + 토스트 문구도 "다시 신청되었어요" 류로 맞추는 게 자연스러움.

## 기획서와 카피/UI 불일치 (Figma 기준으로 갈지 확인)

**5. 확인 UI가 모달이 아니라 바텀시트** — 기획서 3.2/3.3/3.6은 "모달". Figma Description도 "바텀시트 호출"로 명시. Figma 기준으로 진행하면 될지.

**6. 카피가 전부 다름**

| 항목 | 기획서 | Figma |
| --- | --- | --- |
| 오픈 신청 제목 | "스팟을 오픈하면 다른 유저들도 볼 수 있어요" | "MY 스팟을 오픈할까요?" |
| 오픈 신청 취소 버튼 | "다음에요" | "취소" |
| 철회 제목 | "신청을 철회할까요?" | "오픈 신청을 철회할까요?" |
| 철회 취소 버튼 | "계속 기다릴게요" | "취소" |
| 반려 배너 버튼 | "오픈 철회하기" / "내용 보완해서 다시 신청하기" | "스팟 오픈 철회" / "수정 후 재신청" |

**7. 오픈 취소가 버튼+모달이 아니라 "스팟 공개 ON/OFF" 토글**
기획 3.6은 "오픈 취소하기" 버튼 → 확인 모달("좋아요 수는 그대로 유지되고…") 흐름이었는데, 이후 확정된 토글 원칙으로 정리됨:
"최초 오픈 승인 이후에만 나타나며, 승인 이력이 있는 스팟은 이후 ON/OFF 를 검수 없이 자유롭게 전환 가능. OFF 상태는 '나만보기(DRAFT)' 와는 다른 별도 상태로 취급하며, OFF→ON 전환 시 재검수 절차를 거치지 않는다."
→ 확인 모달은 없어지고 즉시 반영되는 토글로 확정. 좋아요/북마크는 기존대로 유지된다.
→ **막힘: 서버 상태 모델(`DRAFT/PENDING/RE_REVIEW_PENDING/PUBLISHED/REJECTED`)에 "승인 이력 있는 OFF" 를 나타낼 상태가 없다.** `DELETE .../publications` 는 해제 후 상태가 항상 DRAFT 이고, `POST .../open-requests` 는 DRAFT 에서 호출하면 항상 재검수(PENDING) 로 간다. 지금 구현은 이 제약 때문에 토글 OFF→DRAFT, 토글 ON→매번 재검수 시트로 되어 있어 확정된 원칙과 다르다. 서버에 상태/엔드포인트 추가가 필요하다(`docs/PV-40/backlog.md` §2 참고).

**8. 재신청 확인 바텀시트("다시 신청할까요?")가 시안에 없음**
기획 3.5는 폼 제출 시 확인 모달이 뜬다고 돼 있는데, 시안은 [등록] → 바로 성공 토스트. 어느 쪽인지.

**9. 뱃지 표기**
기획 3.7은 공개된 유저 스팟에 "유저 등록" 뱃지인데, 시안(본인 화면)은 계속 "MY 스팟". 타인이 보는 화면이 아직 없어서 확인 불가.

## 아직 못 받은 자료 (①③ 잔여)

- **타인/큐레이션 스팟 상세** — 출처 표기 줄("한국관광공사"/"Pickflow 운영자") + "유저 등록" 뱃지 + 추천 버튼이 들어간 화면. ①의 5번째 케이스.
- **반려 사유 5종 문구** — `DUPLICATE`/`LOW_QUALITY`/`LOCATION_MISMATCH`/`FILTER_MISMATCH`/`ETC`. 시안엔 "선택하신 카테고리와 사진이 일치하지 않습니다."(=FILTER_MISMATCH) 하나만. 서버 `reasonLabel`/`guideMessage`를 그대로 쓸지 앱 문구를 따로 둘지.
- **추천 버튼 활성 상태** — 시안엔 비활성(흰 배경 👍)만 있음. 눌린 상태 디자인 필요.
- **미리보기 바텀시트(지도 핀 탭)** 에도 추천이 들어가는지 — API `preview` 응답엔 `likeCount`/`isLiked`/`isLikeable`이 추가됐음.
